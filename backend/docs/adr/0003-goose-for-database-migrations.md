# ADR-0003: goose for database migrations
## Status
Accepted

---

## Context
Backend-приложение использует PostgreSQL как основное хранилище данных. По мере развития проекта структура базы данных будет изменяться: будут появляться новые таблицы, связи, индексы, расширения PostgreSQL и изменения существующих сущностей.

Если изменять структуру базы данных вручную через pgAdmin или отдельные SQL-команды, состояние базы может отличаться у разных разработчиков и в разных средах. Это усложняет командную разработку, развёртывание проекта, тестирование и поддержку.

Миграции позволяют хранить историю изменений схемы базы данных в репозитории и применять эти изменения одинаковым способом в любой среде.

---

## Requirements

Инструмент миграций должен:
- позволять писать миграции на обычном SQL;
- поддерживать применение и откат миграций;
- хорошо работать с PostgreSQL;
- не требовать использования ORM;
- быть простым для локальной разработки;
- легко интегрироваться с Makefile и Docker Compose;
- позволять хранить историю изменений схемы базы данных в Git;
- обеспечивать воспроизводимость структуры базы данных во всех окружениях.

## Decision

В проекте принято решение использовать **Goose** для управления миграциями базы данных.

Миграции хранятся в каталоге `migrations` и применяются через команды Makefile.

Каждое значимое изменение схемы базы данных оформляется отдельной миграцией. Для основных сущностей проекта используется правило:

> одна сущность — одна миграция.

Например:

```text
0001_create_users.sql
0002_create_projects.sql
0003_create_patterns.sql
```
Такой подход позволяет сделать историю изменений схемы базы данных последовательной, понятной и легко отслеживаемой. Каждая миграция отражает одно конкретное изменение структуры базы данных и может быть независимо применена или проанализирована.

---

## Consequences
### Advantages
- позволяет разработчикам писать на обычном SQL, что унифицирует взаимодействие с БД;
- хорошо интегрируется с PostgreSQL;
- не требует использования ORM, что очень важно в нашей ситуации с выбранной технологией для работы непосредственно с самой БД;
- позволяет удобно работать с миграциями за счет предоставления удобств для настройки команд в Makefile;
- позволяет удобно хранить файлики с миграциями в системах контроля версий;
- удобное управление миграциями за счет простой CLI;
- достаточно понятен и прост в освоении;
- история изменений структуры базы данных становится частью репозитория проекта и может отслеживаться системой контроля версий.

### Trade-offs
- использование goose требует уверенного знания SQL;
- goose не предоставляет автоматическое проектирование схемы;
- разработчики должны самостоятельно поддерживать корректную последовательность и согласованность миграций;
- goose не предоставляет сложного визуального моделирования БД.

---

## Alternatives Considered
На этапе проектирования альтернативные инструменты управления миграциями подробно не рассматривались.

Основной целью было выбрать простой, хорошо зарекомендовавший себя инструмент, который:
- ориентирован на Go-проекты;
- поддерживает SQL-first подход;
- хорошо интегрируется с PostgreSQL;
- не требует использования ORM.

По результатам предварительного анализа этим требованиям наиболее полно соответствовал Goose, поэтому дальнейшее сравнение с другими инструментами не проводилось.

## Why This Decision Fits This Project
Проект Nesting Optimizer предполагает активное развитие структуры базы данных. По мере реализации новых возможностей будут появляться новые сущности, ограничения, индексы и изменения существующих таблиц. Поэтому управление схемой базы данных должно быть таким же контролируемым процессом, как и разработка исходного кода.

Ранее в проекте было принято решение использовать библиотеку sqlx, основанную на явном написании SQL-запросов. Использование Goose логично продолжает выбранную архитектурную концепцию, поскольку миграции также описываются обычным SQL без дополнительных уровней абстракции.

Такой подход обеспечивает единый стиль работы с базой данных на всех этапах разработки: как при изменении структуры базы данных, так и при реализации бизнес-логики приложения.

Интеграция Goose с Makefile и Docker Compose делает процесс применения миграций простым, воспроизводимым и одинаковым для всех разработчиков проекта.

В совокупности эти причины делают Goose наиболее подходящим инструментом управления миграциями для данного проекта.
