# ADR-0005: Docker Compose for Local Development

## Status 
Accepted

---

## Context

Backend-приложение использует PostgreSQL с расширением PostGIS в качестве основного хранилища данных.

Для разработки проекта каждому разработчику необходимо иметь одинаковую рабочую среду, включающую сервер базы данных, необходимые расширения и одинаковые версии используемого программного обеспечения.

Установка и настройка PostgreSQL вручную на каждом компьютере приводит к различиям в окружении разработчиков, усложняет подключение новых участников команды и снижает воспроизводимость процесса разработки.

Кроме того, инфраструктура проекта со временем будет расширяться. Помимо базы данных в дальнейшем могут появиться дополнительные сервисы, взаимодействующие друг с другом внутри единой сети.

Поэтому проекту необходим единый механизм локального развёртывания инфраструктуры, позволяющий быстро создавать одинаковое окружение разработки на любом компьютере.

---

## Requirements

Инструмент локального развёртывания должен:
- обеспечивать одинаковое окружение для всех разработчиков;
- автоматически разворачивать необходимые сервисы проекта;
- поддерживать использование PostgreSQL с расширением PostGIS;
- обеспечивать сохранность данных между пересозданием контейнеров;
- позволять централизованно управлять параметрами запуска сервисов;
- поддерживать проверку готовности сервисов к работе;
- быть простым в использовании и запускаться одной командой;
- хорошо интегрироваться с конфигурацией проекта и Makefile.

---

## Decision

В проекте принято решение использовать **Docker Compose** в качестве основного инструмента для локального развёртывания инфраструктуры.

На текущем этапе разработки через Docker Compose запускается только сервер базы данных PostgreSQL с расширением PostGIS. Backend-приложение запускается локально средствами Go (`go run` или соответствующими командами `Makefile`).

Для базы данных используется официальный образ `postgis/postgis`, содержащий PostgreSQL и заранее установленное расширение PostGIS.

Конфигурация контейнера полностью определяется через переменные окружения, что обеспечивает согласованность с общей системой конфигурации проекта.

Для хранения данных используется именованный Docker Volume, позволяющий сохранять содержимое базы данных независимо от жизненного цикла контейнера.

Для взаимодействия сервисов создаётся отдельная Docker-сеть, которая станет основой дальнейшего расширения инфраструктуры проекта.

Для повышения устойчивости среды разработки используются:

- политика автоматического перезапуска контейнера (`restart: unless-stopped`);
- проверка готовности сервиса (`healthcheck`).

Все операции по управлению инфраструктурой выполняются через `Makefile`, что обеспечивает единый способ запуска проекта для всех разработчиков.

---

## Consequences

### Advantages

После принятия данного решения проект получает следующие преимущества:
- все разработчики используют одинаковую локальную инфраструктуру;
- запуск среды разработки выполняется несколькими стандартными командами;
- отсутствует необходимость вручную устанавливать PostgreSQL и PostGIS;
- данные базы сохраняются при пересоздании контейнеров;
- инфраструктура легко расширяется добавлением новых сервисов;
- параметры запуска централизованно управляются через Docker Compose и переменные окружения;
- Makefile предоставляет единый интерфейс управления инфраструктурой проекта.

### Trade-offs

При этом разработчики осознанно принимают следующие компромиссы:
- для работы с проектом требуется установленный Docker;
- запуск контейнеров требует дополнительных системных ресурсов;
- необходимо поддерживать актуальность файла `docker-compose.yml`;
- часть инфраструктурных проблем связана уже не только с приложением, но и с контейнерной средой;
- разработчикам необходимо понимать базовые принципы работы Docker и Docker Compose.

---

## Alternatives Considered

На этапе проектирования были рассмотрены различные способы организации локальной среды разработки.

### Локальная установка PostgreSQL

Данный подход был отклонён, поскольку требует ручной установки и настройки PostgreSQL и PostGIS на каждом компьютере разработчика. Это усложняет подключение новых участников команды, увеличивает вероятность различий между окружениями и затрудняет сопровождение проекта.

### Виртуальная машина

Использование отдельной виртуальной машины также рассматривалось как возможный вариант.

Однако данный подход требует большего объёма системных ресурсов, сложнее в сопровождении и менее удобен для повседневной разработки по сравнению с контейнеризацией отдельных сервисов.

### Полная контейнеризация приложения

Также рассматривался вариант запуска как базы данных, так и backend-приложения через Docker Compose.

На текущем этапе разработки было принято решение контейнеризировать только инфраструктурные сервисы. Backend запускается локально средствами Go, что упрощает отладку, использование инструментов разработки и ускоряет цикл внесения изменений.

По мере развития проекта решение может быть пересмотрено и оформлено отдельным ADR.

---

## Why This Decision Fits This Project

Проект Nesting Optimizer разрабатывается как долгосрочное backend-приложение, архитектура которого предусматривает дальнейшее расширение функциональности и инфраструктуры.

Использование Docker Compose позволяет создать единое воспроизводимое окружение разработки, в котором все разработчики используют одинаковые версии PostgreSQL, PostGIS и одинаковые параметры запуска сервисов. Это значительно уменьшает вероятность возникновения ошибок, связанных с различиями локальных окружений.

Данное решение хорошо сочетается с ранее принятыми архитектурными решениями проекта. Конфигурация сервисов полностью строится на переменных окружения, управление схемой базы данных осуществляется через Goose, а запуск инфраструктуры интегрирован с Makefile.

Контейнеризация на данном этапе ограничивается инфраструктурными сервисами, что позволяет сохранить удобство локальной разработки backend-приложения без преждевременного усложнения процесса разработки.

Таким образом, Docker Compose обеспечивает баланс между простотой локальной разработки, воспроизводимостью окружения и готовностью проекта к дальнейшему развитию.
