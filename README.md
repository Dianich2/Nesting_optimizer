# Nesting Optimizer

Веб-приложение для ручного и автоматического раскроя многоугольников на плоскости. Библиотека хранит исходные поверхности и лекала. При добавлении в проект сервер создаёт отдельный экземпляр с собственной геометрией. Один оригинал можно добавить несколько раз. Поверхности поддерживают отверстия.

## Запуск локально

Требуются Go версии из `backend/go.mod`, Node.js 24, Docker Compose, PostgreSQL с PostGIS и Goose. Для браузерных тестов потребуется Chromium или Chrome.

1. В `backend` скопируйте `.env.example` в `.env` и задайте параметры локальной БД и JWT. Образ PostGIS, порты и том БД определены в `backend/docker-compose.yml`.
2. Из `backend` запустите `docker compose up -d postgres`, проверьте целевое подключение командой `make migrate-status` и на новой или тестовой БД выполните `make migrate-up`. Миграция физического удаления требует проверки резервной копии и отдельного согласования для действующей базы.
3. Из `backend` запустите `go run ./cmd/api`. API по умолчанию использует порт 8082 и принимает запросы браузера с `http://localhost:5173`.
4. Из `frontend` запустите `npm ci` и `npm run dev`. Откройте `http://localhost:5173`. Vite проксирует `/api` на локальный API. Переопределить адрес можно переменной `NESTING_API_TARGET`.

OpenAPI доступен в `backend/docs/swagger.yaml` и через `/swagger/index.html` работающего API.

## Компоненты и данные

- `backend/internal/domain` — сущности. `internal/usecase` — проверки прав, геометрические правила и границы операций. `internal/repository/postgres` — хранение и блокировки. `internal/transport/http` — Fiber, DTO, JWT и маршруты.
- `backend/internal/geometry` — точные операции над многоугольниками. `internal/nesting` — Baseline, NFP Greedy, Genetic Algorithm, Simulated Annealing и Hybrid.
- `frontend/src/features/library` — создание и редактирование контуров, отверстия и поддерживаемый импорт SVG. `features/project-resources` — проектные копии и выбор из библиотеки. `features/nesting` и `pages/NestingPage.tsx` — полотно, редактирование размещений, запуск, история и экспорт.

Проект владеет проектными поверхностями, лекалами, размещениями и запусками раскроя. При удалении библиотечного оригинала ссылка в копии очищается через `ON DELETE SET NULL`, а геометрия копии и её размещения сохраняются. Удаление используемого экземпляра возвращает HTTP 409. Удаление проекта каскадно удаляет его экземпляры, размещения и историю. Удаление пользователя с проверкой пароля удаляет его проекты, библиотеку и сессии.

Миграция `20261115120000_use_physical_deletion.sql` удаляет исторические строки Soft Delete и заменяет частичные индексы. Старые миграции описывают прежнюю схему. Down восстанавливает структуру, история фактически удалённых данных доступна только из проверенной резервной копии.

## Раскрой

На полотне можно добавлять, перетаскивать и поворачивать лекала. Координаты задают центр ограничивающего прямоугольника исходного лекала. Колесо масштабирует вид от указателя. Привязка к сетке включается отдельно. В пределах текущей страницы Undo/Redo выполняет изменения через сервер. Восстановленное удалённое размещение получает новый ID. При конфликте версии сервер сохраняет более свежие изменения.

Автоматические алгоритмы принимают одни и те же параметры. Перед записью сервер проверяет границы, отверстия, взаимные пересечения, повороты и метрики. Режим замены применяется атомарно. При повторе POST с тем же `Idempotency-Key` сервер возвращает сохранённый результат, а другой запрос с этим ключом получает HTTP 409. Маршрут проверки операции возвращает `unknown`, `running`, `failed` или `completed`. После сетевого сбоя интерфейс использует сохранённый в сессии вкладки ключ. Сервер хранит успешный результат до удаления поверхности.

Текущие метрики вычисляются из сохранённых размещений и доступной площади за вычетом отверстий. История показывает метрики отдельных запусков, длительность и режим замены. Для старых запусков нельзя установить полное совпадение исходных условий только по доступным метрикам. SVG экспортирует сохранённую геометрию в координатах поверхности. JSON содержит поверхность, подтверждённые размещения и их метрики.

## Тестирование

В `backend` выполните `go test ./...`, `go test -race ./...`, `go vet ./...` и `golangci-lint run ./...`. Для интеграционных тестов задайте `NESTING_TEST_DSN` для отдельной базы с именем `nesting_test`. Тесты создают уникальные схемы, применяют миграции и оставляют схемы для диагностики. Без DSN интеграционные тесты пропускаются. Рабочая БД для этих операций не подходит.

В `frontend` выполните `npm run build` и `npm run lint`. Из корня выполните `node --test --test-isolation=none frontend/tests/*.test.mjs`. Для Playwright запустите отдельный тестовый API на мигрированной тестовой БД с `HTTP_BROWSER_ORIGIN=http://localhost:5178`. Из `frontend` установите Chromium командой `npx playwright install chromium` или задайте `E2E_CHROME` с путём до установленного Chrome. Задайте `NESTING_API_TARGET` с адресом тестового API и выполните `npm run test:e2e`. Браузерный сценарий регистрирует отдельного тестового пользователя и изменяет только его данные.

См. также [проверки и ручной чек-лист](docs/verification.md).
