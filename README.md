# Nesting Optimizer

Веб-приложение для ручного и автоматического раскроя многоугольников на плоскости. Библиотека хранит исходные поверхности и лекала. При добавлении в проект сервер создаёт отдельный экземпляр с собственной геометрией. Один оригинал можно добавить несколько раз. Поверхности поддерживают отверстия.

## Запуск локально

Требуются Go версии из `backend/go.mod`, Node.js 24, Docker Compose, PostgreSQL с PostGIS и Goose. Для браузерных тестов потребуется Chromium или Chrome.

1. В `backend` скопируйте `.env.example` в `.env` и задайте параметры локальной БД и JWT. Образ PostGIS, порты и том БД определены в `backend/docker-compose.yml`.
2. Из `backend` запустите `docker compose up -d postgres`, проверьте целевое подключение командой `make migrate-status` и на новой или тестовой БД выполните `make migrate-up`. Миграция физического удаления требует проверки резервной копии и отдельного согласования для действующей базы.
3. Из `backend` запустите `go run ./cmd/api`. API по умолчанию использует порт 8082 и принимает запросы браузера с `http://localhost:5173`.
4. Из `frontend` запустите `npm ci` и `npm run dev`. Откройте `http://localhost:5173`. Vite проксирует `/api` на локальный API. Переопределить адрес можно переменной `NESTING_API_TARGET`.

OpenAPI доступен в `backend/docs/swagger.yaml` и через `/swagger/index.html` работающего API.

## Компоненты и данные

- `backend/internal/domain` — сущности. `internal/usecase` — проверки прав, геометрические правила и границы операций. `internal/repository/postgres` — хранение и блокировки. `internal/transport/http` — Fiber, DTO, JWT и маршруты.
- `backend/internal/geometry` — точные операции над многоугольниками. `internal/nesting` — Baseline, NFP Greedy, Genetic Algorithm, Simulated Annealing и Hybrid.
- `frontend/src/features/library` — создание и редактирование контуров, отверстия и поддерживаемый импорт SVG. `features/project-resources` — проектные копии и выбор из библиотеки. `features/nesting` и `pages/NestingPage.tsx` — полотно, редактирование размещений, запуск, история и экспорт.

Проект владеет проектными поверхностями, лекалами, размещениями и запусками раскроя. При удалении библиотечного оригинала ссылка в копии очищается через `ON DELETE SET NULL`, а геометрия копии и её размещения сохраняются. Удаление используемого экземпляра возвращает HTTP 409. Удаление проекта каскадно удаляет его экземпляры, размещения и историю. Удаление пользователя с проверкой пароля удаляет его проекты, библиотеку и сессии.

Новые аддитивные миграции `20261119120000_nesting_operation_lifecycle.sql` и `20261119121000_create_nesting_previews.sql` добавляют жизненный цикл операций, параметры истории и временное хранилище предпросмотров. Перед запуском обновлённого API примените их к проверенной целевой базе по обычной процедуре проекта.

Миграция `20261115120000_use_physical_deletion.sql` удаляет исторические строки Soft Delete и заменяет частичные индексы. Старые миграции описывают прежнюю схему. Down восстанавливает структуру, история фактически удалённых данных доступна только из проверенной резервной копии.

## Раскрой

Чтобы добавить лекало, нажмите «Добавить на поверхность» рядом с его названием и щёлкните по холсту. Контур следует за указателем. Перетаскивание и точный поворот выбранной детали сохраняются через API. Координаты задают центр ограничивающего прямоугольника исходного лекала. Колесо масштабирует вид от указателя. Привязка к сетке включается отдельно. В пределах текущей страницы Undo/Redo выполняет изменения через сервер. Восстановленное удалённое размещение получает новый ID. При конфликте версии сервер сохраняет более свежие изменения.

Автоматические алгоритмы принимают одни и те же параметры. «Предпросмотр» вызывает POST /nesting/preview и возвращает preview_id. «Сохранить предпросмотр» отправляет исходные параметры и preview_id в POST /nesting. Сервер применяет именно показанный результат без повторного запуска алгоритма. Обычный прямой запуск POST /nesting также поддерживается.

Исходные данные читаются согласованно под короткой блокировкой проекта. Оптимизатор и геометрическая проверка работают вне транзакции записи. Финальная транзакция сверяет fingerprint поверхности, используемых лекал и размещений, затем атомарно сохраняет раскладку, историю, результат операции и применение предпросмотра. Изменившийся снимок возвращает HTTP 409 с кодом nesting_stale. Обе семантики keep_existing сохраняются.

Idempotency-Key резервируется в PostgreSQL. Одинаковые запросы используют одну операцию. Другие параметры с тем же ключом дают конфликт. Статус доступен после перезагрузки и рестарта API. running включает ожидание слота, вычисление и финальную запись. completed и failed терминальны. После отмены, timeout или другой записанной ошибки для нового вычисления нужен новый ключ. Просроченная lease становится failed с кодом nesting_timeout. Потерянный ответ после COMMIT восстанавливается по сохранённому результату.

Кнопка отмены отправляет DELETE /nesting/operations/{operation_key}. Операции принадлежат серверу и имеют собственный deadline, поэтому разрыв первого HTTP-соединения не отменяет сохранение. Для предпросмотра действует тот же ограниченный срок выполнения. Управляемые циклы проверяют контекст. Earcut и отдельные вызовы simplefeatures прерываются на границах вызова. Жёсткое принудительное прерывание внутри сторонней функции потребовало бы изоляции процесса.

Лимиты одного расчёта составляют 500 экземпляров, 36 углов и две минуты, включая ожидание ресурсов и финальную запись. Завершение записи терминальной ошибки после отмены имеет отдельный предел 5 секунд. Браузер ожидает вычисление до 130 секунд, последующую синхронизацию — до 10 секунд. Неопределённый результат сохраняет пользовательский ключ в sessionStorage для проверки статуса. Объект восстановления проверяется и привязан к текущему пользователю.

NESTING_WORKERS и NESTING_QUEUE задают число активных задач и мест ожидания. Значения по умолчанию — 2 и 4 на процесс API. Переполнение возвращает HTTP 503 nesting_overloaded. Для повторных POST ограничены 32 ожидающих ответа. Переполнение этого ожидания возвращает 503 nesting_pending и сохраняет исходную выполняющуюся операцию. GET статуса и DELETE отмены обходят вычислительные слоты.

Перед загрузкой снимка PostGIS проверяет бюджет до 100000 хранимых вершин суммарно, 4096 вершин без замыкания на многоугольник, 64 отверстий и 2000 существующих размещений на поверхности. Для NFP дополнительно ограничены 65536 пар треугольников и 200000 кандидатов. Union выполняется порциями до 64 частей с проверками отмены. Эти ограничения относятся к расчёту, библиотечные ресурсы сохраняют прежний формат.

Предпросмотры хранятся в PostgreSQL 15 минут. На пользователя сохраняются до 10 записей, при заполнении вытесняется самая старая. Бюджет исходного payload — 8 МиБ, готового ответа предпросмотра — 8 МиБ, сохранённого результата — 16 МиБ с учётом реальных ID и времени. Истёкшие строки удаляются при создании новых предпросмотров и фоновыми ограниченными проходами при запуске API и раз в минуту. Идемпотентный результат записи хранится независимо от TTL предпросмотра.

Текущие метрики вычисляются из сохранённых размещений и доступной площади за вычетом отверстий. История показывает метрики отдельных запусков, длительность и режим замены. Новые запуски также сохраняют исходные параметры расчёта. При сохранении предпросмотра длительность берётся из первоначальной оптимизации. Для старой истории параметры остаются неизвестными. Для старых запусков нельзя установить полное совпадение исходных условий только по доступным метрикам. SVG экспортирует сохранённую геометрию в координатах поверхности. JSON содержит поверхность, подтверждённые размещения и их метрики.

## Тестирование

В `backend` выполните `go test ./...`, `go test -race ./...`, `go vet ./...` и `golangci-lint run ./...`. Для интеграционных тестов задайте `NESTING_TEST_DSN` для отдельной базы с именем `nesting_test`. Тесты создают уникальные схемы, применяют миграции и оставляют схемы для диагностики. Без DSN интеграционные тесты пропускаются. Рабочая БД для этих операций не подходит.

В `frontend` выполните `npm run build` и `npm run lint`. Из корня выполните `node --test --test-isolation=none frontend/tests/*.test.mjs`. Для Playwright запустите отдельный тестовый API на мигрированной тестовой БД с `HTTP_BROWSER_ORIGIN=http://localhost:5178`. Из `frontend` установите Chromium командой `npx playwright install chromium` или задайте `E2E_CHROME` с путём до установленного Chrome. Задайте `NESTING_API_TARGET` с адресом тестового API и выполните `npm run test:e2e`. Браузерный сценарий регистрирует отдельного тестового пользователя и изменяет только его данные.

См. также [проверки и ручной чек-лист](docs/verification.md).

Повтор keyed-предпросмотра возвращает тот же preview_id, пока запись доступна в TTL-кэше. Одновременные запросы предпросмотра объединяются в пределах одного процесса API; координация незавершённых предпросмотров между несколькими процессами пока отсутствует. Идемпотентность сохранения обеспечивается PostgreSQL между процессами и после рестарта. Отмена незавершённого предпросмотра требует того же процесса API.
