## Дефект и воспроизведение

В исходном `previewRun` pending создавался до POST; catch очищал его только при nesting_cancelled/nesting_timeout/preview_expired. Поэтому 400 validation_error оставлял блокирующую запись. Backend.Validate отклоняет 501 экземпляр до Reserve, GET возвращает unknown. Форма проверяла формат количеств и углов, но не суммы 500 и длины 36.

Исходная причина подтверждена анализом кода. Исправление закрыто браузерной регрессией: после допустимого UI-запроса перехватчик меняет отправляемое тело на 501 и передаёт его настоящему тестовому API. API реально возвращает 400; после доставки этого ответа pending отсутствует и кнопка нового preview доступна. Это не синтетическая подмена ответа. Отдельного запуска E2E на старом коммите не выполнялось.

## План и таблица переходов

План перед реализацией: отделить классификацию POST-ошибок и предвалидацию в небольшой чистый модуль; подключить их только к preview; сохранить UUID при неопределённости; добавить подтверждаемое локальное закрытие ожидания; проверить ошибки до/после отправки и старое восстановление completed.

| Событие | Ранее | Теперь |

| TCP/Abort/timeout/proxy 502/503/504, неожиданный 500 | Pending | Тот же UUID; никаких автоматических новых POST; явное объяснение неопределённости |

| Save POST/status/retry | Существующий durable-поток | Не изменён; команды закрытия ожидания save нет |

## Классификация

Решение опирается на пару HTTP-статус + прикладной код, а не на все 4xx/5xx разом.

- rejected: 400 validation_error; первый 401 unauthorized_error / 403 forbidden_error; 404 not_found_error / preview_expired; 409 nesting_stale / nesting_cancelled / nesting_interrupted; 408 nesting_timeout; 503 nesting_overloaded.
- check_status: 409 conflict_error; auth-отказ повторного POST. По GET completed восстанавливается результат, по failed снимается ожидание, running/unknown или ошибка GET сохраняют ключ.
- uncertain: сеть, AbortError/TimeoutError, неизвестные/несогласованные пары статуса и кода, HTTP без прикладного кода, nesting_pending и неожиданный internal_error. Сохраняется pending и прежний UUID.

400 может возникнуть до или после Reserve. В обоих случаях достоверный прикладной validation_error является отказом именно этого запроса; исправление не утверждает, что строки операции не существует. Для конфликта ключа это предположение неприменимо, поэтому выполняется reconciliation. Ошибка авторизации повтора также не доказывает прекращение первого запроса.

## Валидация

Проверяется сумма по всем выбранным лекалам <=500, целые положительные количества и хотя бы одно лекало; <=36 элементов списка углов; непустые элементы и конечные числа в [0,360). Нулевые количества невыбранных лекал отфильтровываются. Дубли углов не запрещены; лимит применяется до дедупликации, как Backend.Validate. Порядок/нормализация API не менялись. Серверная валидация остаётся окончательной.

## Безопасность save и гонок

Классификатор preview не используется `runNesting` для сохранения. Диалог закрытия доступен только kind=preview и повторно проверяет текущий operation, UUID и owner/project/surface при подтверждении. Save/посторонние записи не удаляются. `sessionStorage.clear()` отсутствует. Закрытие ожидания не отправляет новый POST и не выдаётся за серверную отмену. Указано, что новый вычислительный запуск после закрытия — осознанное действие пользователя.

Защита `pending.current` сохраняет сериализацию UI-мутаций. Не добавлены polling-таймеры, автоматические ретраи или новый state manager. GET unknown не меняет UUID; pending после reload проверяется прежним owner/scope/kind-валидатором. Undo/Redo, размещения и история при preview не изменяются.
